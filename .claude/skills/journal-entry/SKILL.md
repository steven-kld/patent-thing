# Запись в журнал испытаний

Журнал существует ради одного факта: гипотеза и правило её принятия зафиксированы **до** того, как автор увидел результат. Всё остальное в этом скилле подчинено этому.

Запись делается **только** через `tools/journal.py`. Прямая запись в `journal.jsonl`, редактирование существующих строк, `git commit` журнала руками — запрещены. Скрипт сам ставит `id` и `ts`, сам коммитит, и отказывает при нарушении инвариантов. Если скрипт отказал — покажи текст отказа пользователю и остановись. Не обходи отказ.

## Три правила, которые скрипт проверить не может

Они целиком на тебе.

1. **`claim`, `decision_rule` и `reason` вносятся дословно, как их сформулировал пользователь.** Не переписывай, не «уточняй формулировку», не дополняй, не переводи. Ты имеешь право отказать и переспросить — но не заполнить за него.
2. **Не бери значения полей из контекста сессии.** Если в этой же сессии гонялась модель и ты видел вывод, ты не имеешь права предложить `claim`, `decision_rule`, `values` или `verdict` из увиденного. Единственное исключение — `config`, если он читается механически из кода или конфиг-файла в репозитории: тогда покажи, что прочитал, и попроси подтвердить.
3. **Во время `register` не задавай ни одного вопроса про результат.** Если пользователь начинает диктовать число — останови и объясни, что результат вносится отдельным событием после коммита гипотезы.

Причина: запись, сформулированная тем, кто уже видел результат, формально пройдёт все проверки скрипта и при этом будет подгонкой. Порядок коммитов защищает от неё только если содержимое `claim` не восстановлено постфактум.

## Диалог

Спрашивай по одному пункту. Не показывай форму целиком, не заполняй заранее.

**Шаг 1. Что вносим — гипотезу или результат?**

`register` — гипотеза, прогона ещё не было.
`result` — результат по ранее зарегистрированной гипотезе.

Если пользователь говорит «занеси испытание, вот результат» — это два события. Сначала `register`, коммит, потом `result`. Скрипт всё равно откажет, но лучше сказать это до, а не после.

**Шаг 2 (только для `result`). Проверь, что гипотеза закоммичена.**

```bash
python tools/journal.py verify
```

Показывает открытые `register` без результата. Если нужного id там нет — дальше не идём.

**Шаг 3. Поля.**

Для `register`, по одному, в этом порядке:

| поле | что это | отказывай, если |
|---|---|---|
| `type` | `предрегистрация` / `гейт` / `данные` / `конфигурация` / `аудит` / `решение` | не из списка |
| `claim` | утверждение с заранее названным исходом | это тема, а не утверждение («проверял num_leaves») |
| `metric` | по какой метрике будет судиться | пусто |
| `split` | `train` / `valid` / `test` / `n/a` | не из списка |
| `decision_rule` | что считается «принято», числом | нет числа или сравнения |
| `config` | объект: полная конфигурация прогона | не объект, или неполон настолько, что прогон не воспроизвести |
| `data_ref` | какая выгрузка/таблица использована | пусто |

Для `result`:

| поле | что это |
|---|---|
| `refs` | id гипотезы |
| `values` | объект метрика → число; метрика из `register` обязана присутствовать |
| `artifact` | `{"path": "..."}`; `sha256` посчитает скрипт |
| `verdict` | `принято` / `отвергнуто` / `н/п` |
| `reason` | коротко, словами пользователя |

**Шаг 4. Покажи собранный JSON целиком и дождись подтверждения.** Без подтверждения не запускай скрипт.

**Шаг 5. Запись.**

```bash
echo '<json>' | python tools/journal.py register
echo '<json>' | python tools/journal.py result
```

Скрипт добавит `id`, `ts`, `code_commit` (для `register`) или `register_commit` (для `result`), допишет строку и сделает коммит. Покажи пользователю итоговую запись.

## Особые случаи

**Запись №1** — только `type: "предрегистрация"`, и в `config` обязателен `brief_sha256` — хеш замороженной редакции брифа. В `config` идут текстом константы, которые нельзя менять: правило решения, окно, когорта, границы сплитов, размеры сеток, seed. Не ссылкой на бриф — текстом.

**Исправление ошибочной записи.** Команд `edit` и `delete` нет. Исправление — новое событие `type: "решение"` с `refs` на исправляемый id и объяснением в `claim`. Старая строка остаётся.

**Отменённая или сломавшаяся попытка** получает `result` с `verdict: "н/п"` и причиной. Она не исчезает: число перебранных гипотез — это то, ради чего журнал ведётся, и занижать его нельзя.

**Скрипт отказал с «рабочий journal.jsonl не является продолжением закоммиченного»** — строки правили в обход. Не чини сам, не перезаписывай файл. Попроси пользователя сделать `git diff -- journal.jsonl` и остановись.

## Чего не делать

- Не предлагать формулировки `claim` и `decision_rule`.
- Не заполнять поля из того, что видел в сессии.
- Не объединять `register` и `result`.
- Не редактировать `journal.jsonl` никаким инструментом, кроме этого скрипта.
- Не коммитить журнал вручную.
- Не «прибираться» в журнале.
